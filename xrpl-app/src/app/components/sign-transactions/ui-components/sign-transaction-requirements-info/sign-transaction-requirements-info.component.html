Sign & Submit Transactions

Prepare, sign (single, regular key, or multi-sign), preview JSON, and submit any XRPL transaction type. Supports getting unsigned/signed blobs, copying/downloading JSON, and viewing results — ideal for manual tx crafting, testing, or advanced workflows.

📝 Important Notes:
  • All signing happens **client-side** — your secret/seed never leaves your device.
  • Transaction JSON: Must be valid XRPL format (TransactionType, Account, Sequence, etc.). Edit directly in the preview area.
  • Supports multiple signing modes:
    • Single key (master or regular)
    • Multi-sign (if SignerList set and quorum met)
  • Get Transaction JSON: Generates base JSON for the selected type (you fill in details).
  • Signed Transaction: Produces the signed blob (hex string) ready for submission or multi-sign addition.
  • Submit Transaction: Broadcasts to the connected XRPL node — result shows tesSUCCESS (included) or error codes (tec/tef/tem).
  • Copy/download buttons let you save unsigned/signed JSON or blobs for offline use, sharing, or later submission.
  • Transaction preview shows full details before signing/submitting — use to verify fields, fees, and paths.

⚠️ Security & Submission Risks

Signing exposes control — wrong JSON or compromised device can lead to fund loss or failed txs.

  • Never paste real secrets/seeds into untrusted tools — this page signs locally, but verify your environment.
  • Invalid JSON (missing Sequence, wrong Account, invalid fields) causes submission failure (tem/tef codes) and fee burn.
  • Multi-sign requires quorum — incomplete signers cause tecNO_PERMISSION or similar errors.
  • Submitting the same signed blob twice fails (tesSUCCESS only on first inclusion) — always use fresh signatures.
  • High fees or malformed tx can lock funds temporarily (e.g., escrows, offers) — double-check before submit.
  • Always test full flows (prepare → sign → submit) on devnet or Testnet first — mainnet mistakes are irreversible and cost real XRP.
