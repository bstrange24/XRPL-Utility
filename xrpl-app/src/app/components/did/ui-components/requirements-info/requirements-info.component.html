Decentralized Identifier (DID)

Decentralized Identifiers (DIDs) allow XRPL accounts to publish a self-sovereign identity document following the W3C DID specification. Use DIDSet to create or update your DID document containing verification keys, authentication methods, and service endpoints.

🆔 Create / Update DID DIDSet
Data ➕ Optional
(compressed DID document JSON)
URI ➕ Optional
(external DID document location)
Flags ➕ Optional
(control options or permissions)
📝 Important Notes
  • Requires the DID amendment to be enabled on the network.
  • The DID is derived from the XRPL account address controlling it.
  • DID documents typically contain verification methods, authentication keys, and service endpoints.
  • Data is limited in size (~1 KB compressed).
  • Use URI to reference larger documents stored off-chain (IPFS, HTTPS, etc.).
  • The DID ledger object consumes an owner reserve (~0.2 XRP) until deleted.
  • DID documents are publicly readable from the ledger.

Delete DID

DIDDelete removes the DID ledger object associated with the account. This frees the owner reserve and removes the DID document from the ledger.

🗑 Delete DID DIDDelete
Account Authorization ✅ Required
(must control the DID account)
Signer ➕ Optional
(multi-sign or delegate)
📝 Important Notes
  • Only the controlling account (or authorized signer) can delete the DID.
  • Deleting removes the DID ledger object and releases the owner reserve.
  • Dependent objects referencing the DID may prevent deletion.
⚠️ Control Risks

DID control depends entirely on the XRPL account keys.

  • Losing access to account keys means losing the ability to update or delete the DID.
  • DID documents are public — avoid including sensitive or private information.
  • Incorrect documents require another DIDSet transaction to fix.
  • Always test DID workflows on Testnet or Devnet before mainnet deployment.
