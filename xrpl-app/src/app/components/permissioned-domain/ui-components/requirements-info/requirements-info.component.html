Permissioned Domains

Permissioned Domains allow XRPL accounts to define controlled environments where access can be restricted using credentials or other verification rules. Applications can check these domains before allowing users to interact with specific features.

Requirements by Action

🌐 Create / Update Domain
DomainID Required
Owner Implicit (your account)
URI Optional
Flags / Metadata Optional

📝 Important Notes

  • Requires the PermissionedDomains amendment.
  • Each domain object consumes an owner reserve (~0.2 XRP).
  • Domains act as access control anchors for applications.
  • Credential requirements are enforced off-ledger by the application.
  • The URI field can point to documentation describing the domain rules.

Delete Permissioned Domain

PermissionedDomainDelete removes the domain object from the ledger and frees the owner reserve associated with it.

Requirements

🗑 Delete Domain
DomainID Required
Authorization Must be domain owner

📝 Important Notes

  • Only the domain owner can delete it.
  • Deletion releases the owner reserve.
  • Applications depending on the domain may lose access control functionality.
⚠️ Operational Risks
  • Deleting a domain may immediately revoke access to users relying on it.
  • Applications should handle domain deletion gracefully.
  • Always test domain lifecycle flows on Testnet before mainnet.
}
