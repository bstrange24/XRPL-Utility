Permissioned Domains

Permissioned Domains allow XRPL accounts to define controlled environments where access can be restricted using credentials or other verification rules. Applications can check these domains before allowing users to interact with specific features such as trading pairs, lending pools, or payment channels.

🌐 Create / Update Domain PermissionedDomainSet
DomainID ✅ Required
(unique identifier for the domain)
Owner ✅ Implicit
(your XRPL account)
URI ➕ Optional
(off-chain rules or documentation)
Flags / Metadata ➕ Optional
(application-specific settings)
📝 Important Notes
  • Requires the PermissionedDomains amendment.
  • Each domain object consumes an owner reserve (~0.2 XRP).
  • Domains act as access control anchors for applications.
  • Credential requirements are usually enforced off-ledger by the application.
  • The URI field can point to documentation describing the domain rules.

Delete Permissioned Domain

PermissionedDomainDelete removes the domain object from the ledger and frees the owner reserve associated with it.

🗑 Delete Domain PermissionedDomainDelete
DomainID ✅ Required
Authorization ✅ Must be domain owner
📝 Important Notes
  • Only the domain owner can delete it.
  • Deletion releases the owner reserve.
  • Applications depending on the domain may lose access control functionality.
⚠️ Operational Risks
  • Deleting a domain may immediately revoke access to users relying on it.
  • Applications should handle domain deletion gracefully.
  • Always test domain lifecycle flows on Testnet before deploying to mainnet.
