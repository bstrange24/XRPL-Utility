XRPL Multi-Purpose Tokens (MPTs)

Multi-Purpose Tokens are an advanced fungible token standard on the XRPL with on-chain metadata, supply controls, transfer fees, and compliance features.

🔐 Authorization Rules Critical
Holder Self-Authorization ✅ ALWAYS REQUIRED
Issuer Authorization
(tfMPTRequireAuth) Only if flag enabled
📝 Important Notes:
  • Metadata is immutable once set (max 1024 bytes, XLS-89 format).
  • Each MPT issuance + each holder’s balance uses owner reserve.
  • Recipients must self-authorize before they can receive any MPT balance.


🔐 MPT Authorization Flow
  • Always: Every recipient must submit MPTokenAuthorize from their own wallet (Flags = 0). This is the "opt-in".
  • If tfMPTRequireAuth flag was set during creation:
    • The issuer must also submit MPTokenAuthorize for that holder.
  • If tfMPTRequireAuth is NOT set:
    • Only the recipient’s self-authorization is needed.
    • Issuer authorization is not required (but harmless if done).


⚠️ Common Gotchas
  • You cannot send MPTs to an account that has not self-authorized yet.
  • Authorization is per-issuance (one per MPT type per account).
  • Once authorized, the account has an MPToken ledger entry (even with 0 balance).
  • Destroying an MPT issuance is only possible if there are no holders left.


⚠️ Irreversible & Compliance Considerations

Many MPT properties are permanent after creation.

  • Metadata and most flags cannot be changed post-issuance.
  • Supply cap (if set) is hard — cannot issue more.
  • Non-transferable MPTs cannot be moved at all.
