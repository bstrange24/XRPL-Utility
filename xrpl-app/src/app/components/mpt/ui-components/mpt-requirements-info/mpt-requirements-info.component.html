XRPL Multi-Purpose Tokens (MPTs)

Multi-Purpose Tokens are an advanced fungible token standard on the XRPL with on-chain metadata, supply controls, transfer fees, and compliance features.

Authorization Rules

Authorization Rules
Holder Self-Authorization Always Required
Issuer Authorization (tfMPTRequireAuth) Only if flag enabled

Important Notes

  • Metadata is immutable once set (max 1024 bytes, XLS-89 format).
  • Each MPT issuance + each holder’s balance uses owner reserve.
  • Recipients must self-authorize before they can receive any MPT balance.
MPT Authorization Flow
  • Always: Every recipient must submit MPTokenAuthorize from their own wallet (self-opt-in).
  • If tfMPTRequireAuth flag was enabled: Issuer must also authorize the holder.
  • If tfMPTRequireAuth is NOT set: Only recipient self-authorization is needed.
Common Gotchas
  • You cannot send MPTs to an account that has not self-authorized.
  • Authorization is per-issuance (one per MPT type per account).
  • Destroying an MPT is only possible if there are no holders left.
  • Many properties (metadata, flags, supply cap) are permanent after creation.
